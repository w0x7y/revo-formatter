# Independent review of the Revo syntax inventory

Reviewed 2026-10-05 against the local primary source at `/tmp/revo-formatter-upstream`, whose `HEAD` is `b571298b6fc95bc863548f118354c8d077792f6f`. The checkout was clean. This was a bounded source review of the named formatting risks. I did not run Zig tests, and no upstream or inventory files were edited.

**Requirement compliance.** The inventory supports a Rust formatter with pinned frontend validation, line-width reflow, and exact literal/comment preservation. It correctly distinguishes a conservative whitespace pass from full reflow, requires original and candidate parse success, structural equivalence, concrete-byte preservation, and idempotence. It also correctly makes width a soft limit when syntax or opaque literals prevent a safe break. The missing toolchain pin below should be addressed before treating the validation behavior as reproducible. The record-field doc path should join the preservation fixtures.

**Research quality.** The central claims are accurate and unusually specific about upstream quirks. The distinction between raw token ends and AST span ends is supported by source, as are the same-start-line bare-call rule and dedent's independence from the literal's opening column. The source references are useful. This review found no Critical defect in the safety argument for the inspected revision. That argument remains conditional on a correct lexer, per-gap ASCII whitespace treatment, and preserving complete concrete byte ranges, as the inventory already acknowledges.

| Severity | Finding | Required response |
| --- | --- | --- |
| Critical | None found in the inspected risks. | No correction required. |
| Important | Pinning the Revo commit alone does not pin all frontend behavior. | Record and fix the Zig compiler build used to construct the validator. |

The Important finding follows from the lexer calling `std.zig.string_literal.parseEscapeSequence` for ordinary, multiline, and backtick strings. The implementation of that decoder comes from the compiler's standard library. Upstream's build manifest declares a minimum Zig version of `0.17.0`, and its README asks for `0.17.0`; neither identifies the exact build used by a formatter bridge. A fixed Revo source revision and the same parser options are necessary, but an exact compiler version/build is also part of the reproducibility contract. This is a missing dependency pin, not evidence that the inspected escape claims are currently wrong. See [Lexer.zig, ordinary escapes](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L700), [multiline escapes](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L859), [backtick escapes](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L1003), [build.zig.zon](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/build.zig.zon#L5), and [README](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/README.md#L31).

The first Minor finding concerns the statement that declaration docs attach to the next declaration or method definition. The type parser also consumes `#* ... *#` before record fields, trims the text, and stores it on named, optional, and positional fields. Repeated field docs overwrite the pending field doc, so the last one determines its semantic value. Ordinary comments are skipped there. Full structural comparison must therefore include `TypeExpr.record` field docs and optionality. The inventory's complete-AST requirement already implies that, but its concrete attachment inventory is incomplete. See [type_syntax.zig:191](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/type_syntax.zig#L191), through line 225, and [RecordField](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/ast.zig#L56).

The second Minor finding is a precision improvement to an otherwise correct validation requirement. `Node.synthetic_block` lives outside `Expr`. The parser sets it on the implicit top-level block and synthesized multi-import block; prelude merging reads it to decide whether to flatten a block or preserve its scope. Comparing only the `Expr` union would be incomplete, even with every union payload retained. The inventory says to compare the complete AST, so this is not an identified contradiction. Name the flag to prevent an easy bridge implementation mistake. See [Node](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/ast.zig#L485), [top-level parsing](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L205), [multi-import parsing](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L1236), and [prelude merging](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/pipeline.zig#L506).

The following named risks were corroborated directly:

- Ordinary calls compare `(` to the previous raw token's end, while generic calls compare `<` to the receiver's AST end. Comment-skipping `peek` changes parser position, so a block-comment end can affect ordinary-call adjacency. Source-derived fixture pairs such as `f ##c##(x)` and `f ##c## (x)` should remain in the regression set. [Call paths](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L310), [comment skipping](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L1741).
- Bare calls in statement mode compare the next token's line to the callee AST span's starting line. Open `for` bounds and optional labels use actual byte adjacency. The inventory correctly avoids treating all newlines as statement separators. [Bare calls](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L1475), [labels](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L1014), [for ranges](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L1097).
- Doc/module spans omit delimiters and can also omit one leading body LF. Recovering a full doc range by blindly subtracting two from token start is unsafe. Complete comment ranges must come from concrete scanning. [Doc scanner](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L567).
- Triple-quoted dedent uses decoded bytes, counts tabs as one byte, includes whitespace-only nonempty lines in the minimum, and strips trailing empty lines after dedent. Preserving the whole literal protects closing-line indentation and escaped initial LF behavior. [Dedent](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L921).
- Identifier suffixes, atom continuation, annotation colons, number punctuation, and combined operators create genuine token-boundary hazards. The two-space editor setting is explicit. A width of 80 or 100 remains a design choice; this review did not independently recount the guide's fenced-code statistics. [Token dispatch](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L415), [number scanner](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L640), [identifier/atom rules](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Lexer.zig#L1067), [editor setting](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/docs/editors.md#L147).
- `parseSourceReport` uses lexing and parsing without the compilation pipeline, checks recovered diagnostics, and top-level parsing requires EOF. The bridge should treat both `.err` reports and returned Zig errors as failure. The inventory's non-destructive-failure requirement covers that latter case. [Frontend entry](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L99), [report completion](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L167), [EOF check](https://github.com/if-not-nil/revo/blob/b571298b6fc95bc863548f118354c8d077792f6f/src/lang/Parser.zig#L205).

Verdict: use the inventory as the syntax baseline, with the compiler pin and small completeness clarifications above. This review does not establish that a future Rust scanner or AST serialization is correct; those still need the proposed fixtures and validation checks.
